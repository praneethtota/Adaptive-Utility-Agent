1. The problem this solves

Deployed language models are static artifacts. Once released, their behavior is frozen. If a model produces a wrong answer today — a hallucination, a complexity claim that contradicts the code, a medical fact that has since been updated — it will produce the same wrong answer tomorrow, and every day until the next version ships months later. There is no feedback loop between detected errors and model behavior between releases.

The cost is asymmetric by domain. A wrong recipe suggestion is inconsequential. A wrong drug dosage, a wrong legal interpretation, a wrong structural calculation — these have real consequences that accumulate silently until a release cycle closes the gap.

This framework builds the feedback loop. It wraps any LLM or set of LLMs with an adaptive utility layer that:

  • Routes queries to the specialist most likely to answer them correctly
  • Detects contradictions in outputs automatically, without human annotation
  • Injects corrections into future sessions immediately — no retraining required for session-level fixes
  • Accumulates training pairs from detected errors, weighted by domain stakes
  • Calibrates specialist weights through LoRA fine-tuning cycles with utility-gated promotion
  • Abstains when confidence falls below a domain-specific floor, rather than producing confident wrong answers

The governing mechanism is a utility function that acts as a control law over all of these behaviors simultaneously. The same function that scores individual responses also drives the training loss weighting, the abstention gate, and the blue-green promotion decision.

2. Architecture overview

The system has six components. Every component is independently deployable and testable. Start with just the correction loop on a single model and add components incrementally.

Component 1

Specialist Graph

N independently deployed domain models. Each has its own weights, training pipeline, and deployment cycle. Updating one specialist cannot affect another — no shared parameters.

Component 2

Router

FastAPI process that classifies queries and dispatches to the right specialist. Single-domain queries route to one specialist. Ambiguous queries fan out to multiple and go to the Arbiter.

Component 3

Correction Loop

Three layers: per-session behavioral injection (seconds), calibration-cycle DPO fine-tuning (hours), release-level distillation (monthly). Contradictions detected automatically at each layer.

Component 4

Arbiter Agent

Resolves cross-domain conflicts through four structured checks: logical, mathematical, cross-session, empirical. Verified corrections become DPO training signal.

Component 5

Blue-Green Deployment

Utility-deviation-triggered traffic split. GREEN promoted only when U_green exceeds U_blue by δ(field) for T(field) consecutive interactions. Self-regulating softmax routing.

Component 6

Utility Function

U = w_e·E + w_c·C + w_k·K. The control law governing all component behaviors simultaneously. Field-specific weights derived from societal licensing standards.

4. The utility function

Every component in the system is governed by one formula:

U = w_e(f) · E  +  w_c(f) · C  +  w_k(f) · K

  E -- Efficacy:    how well the output serves the platform's definition
                   of a good outcome. Domain-defined: in SWE, E measures
                   test pass rate vs human baseline. Business objectives
                   are not a separate term -- they shift what E means.

  C -- Confidence: internal consistency, penalised by contradictions.
                   Below C_min(field): ABSTAIN.

  K -- Curiosity:  exploration bonus toward high-upside unexplored domains.
                   Capped at 50% to prevent gaming.

  f -- field context, determines weights and bounds.

This is not arbitrary. It is the unique additive structure satisfying five behavioral axioms via Debreu's representation theorem. The EMA rate α=0.2 is Kalman-optimal for this noise model. See Appendix B.

μ(f) is the key parameter. The field penalty multiplier is the direct DPO loss weighting mechanism. A surgery error contributes 10× more gradient than a creative writing error. The utility function governs what the model learns to fix, not just how it is evaluated.

5. Field classifier and routing

The field classifier maps a query to a probability distribution over domains. The router uses this to route to one specialist (confident) or fan out to multiple (ambiguous).

5.1 Three robustness mechanisms

  • High-stakes floor: Surgery, aviation, and law are floored at 15% if they appear at all. A 5% medical signal becomes 15% — over-caution costs less than under-caution.
  • EMA history: Field drift across a conversation is tracked at α=0.4. A conversation drifting from SWE into medicine shows tightening bounds over turns.
  • Entropy fallback: High entropy shifts mass toward the most conservative field present. Ambiguity increases caution, not averaging.

5.2 Regime 2 — the failure mode to monitor

Regime 2 is when a query routes to the wrong specialist with high confidence. Measured signature on RTX 4090: mismatched routing showed mean confidence 0.750 vs ~0.60 for correctly-routed arms. Brier score tied with no-routing (0.279 vs 0.280) despite higher raw pass rate. The wrong-domain specialist is more confident outside its domain — calibration failure, not accuracy collapse. Monitor routing accuracy continuously in production.

6. The correction loop

Three layers operating at different timescales, all active simultaneously in a deployed system.

6.1 Layer 1 — Per-session injection (seconds)

When a contradiction is detected, a corrective assertion is injected into the system prompt for the remainder of the session. No weight changes. Cost: ~100ms. Prevents a user from receiving the same wrong answer twice in the same conversation.

6.2 Signal decay classes

ClassSignalDecayRationale
AExplicit rejection, verified contradictionNeverA verified error doesn't become less wrong over time.
BStrong positive (saves, verified correct)τ = 10yrStable knowledge.
CModerate engagement (completions, ratings)τ = 3yrSubject to domain evolution.
DWeak signal (clicks, views)τ = 6moNoisy — fast decay prevents stale influence.

6.3 Layer 2 — Calibration-cycle DPO (hours)

Each contradiction generates a (prompt, chosen, rejected) DPO pair. Training loss weight = μ(f). A surgery correction contributes 10× more gradient than a creative writing correction. The utility function is the training loss, not just a metric.

6.5 Layer 3 — Release-level distillation (monthly)

Accumulated LoRA adapters merge into a new base fine-tune. Field penalty weighting ensures surgery corrections contribute 10× more than creative writing corrections to the merged base. Categorically different from existing continual learning approaches that treat all corrections equally.

7. DPO pair accumulation

DPO pairs accumulate automatically from the harness — no human annotation. A pair is created when cycle N produces a contradiction and cycle N+1 produces fewer after correction injection.

  --cycles 3 --queries seeded_contradictions.json \
  --export-dpo dpo_pairs/swe_accumulation.json \
  --field software_engineering --temperature 0.2 --append \

# Check progress
python -c "
import json
d = json.load(open('dpo_pairs/swe_accumulation.json'))
entries = d if isinstance(d, list) else d.get('entries', [])
paired = [e for e in entries if e.get('chosen') and e.get('rejected')]

Seed query design. Two reliable patterns that fire the current detector: (A) claim O(n) or O(1) time but require nested loops, (G) claim O(n) but require string += in a loop. Queries around recursive algorithms, graph complexity, or off-by-one correctness will not fire. Design around the two patterns above, or extend the detector before designing around new patterns.

Target dataset size. POC minimum: 50 paired entries. Production quality: 500+ across temperature runs 0.2 → 0.4 → 0.6 → 0.8. Run parallel sessions against different specialists — two sessions against the same specialist compete for KV cache and slow each other 2–3×.

9. The Arbiter and VCG arbitration

The Arbiter resolves conflicts when multiple specialists produce different outputs for the same query. In the minimal setup it is a 3B generalist model. At scale it implements the VCG mechanism for incentive-aligned verdicts.

9.1 Four verdict cases

  • Case 1/2 — One model wrong: Correction issued to losing model. DPO pair added with weight μ(f).
  • Case 3 — Both wrong: Corrections to both. Curiosity gap bonus K_gap = K_eff × (1 + μ(f)/10) preferentially routes queries on the contested subject until both models achieve C(S) ≥ C_min(f) with no new contradictions over T(f) interactions.
  • Case 4 — Inconclusive: Controlled external escalation to verified domain experts, gated by trust threshold τ(f) ∈ {0.90, 0.80, 0.70, 0.65}. Expert responses re-enter as weighted empirical evidence.

9.2 VCG at scale

VCG replaces fixed arbiter weights with endogenous Clarke transfers. Each specialist's report determines its own DPO penalty weight. Truthful reporting is the dominant strategy (Theorem S1, §10.6). Implement when: 3+ separately calibrated specialists with different confidence profiles, and arbitration volume makes periodic human sampling a real cost. Use a 70B arbiter model as the VCG engine for the initial implementation — one inference call instead of N×M cross-scoring calls.

Upgrade the Arbiter before upgrading specialists. A 3B arbiter making Case 4 decisions on conflicts between 13B specialists will misfire systematically. Arbiter quality determines correction loop quality. Go 3B → 7B → 13B Arbiter before scaling specialist model size.

11.1 Minimal path from POC to production

1
Validate two blue-green cycles

Confirm U improves cycle over cycle on real models. Empirical foundation. Do not add specialists until this is measured.

2
Add a third specialist

Medicine or law. One new specialist doubles cross-domain arbitration opportunities and adds the domain where correction loop value is highest.

3
Upgrade the Arbiter to 13B

More impact on correction quality than adding more specialists. Upgrade arbiter first.

4
Add high-availability routing

Duplicate the router behind a load balancer. Store domain confidence EMA in Redis. Boundary between demo and production service.

5
Implement VCG at 5+ specialists

70B arbiter as VCG engine for the initial implementation. See §9.2.

6
Scale by demand

Add domains when routing shows measurable fallback rates. Upgrade model size (7B → 13B → 34B) when domain error rates justify hardware cost. Each addition is independent — no system-wide rebuild.

12. What not to build first

These are the most common mistakes. All make the first working system harder to build without making it better.
  • Do not build VCG before 3+ calibrated specialists. VCG requires value functions from independently calibrated models. Uniform specialists with no DPO history give the mechanism nothing to compute.
  • Do not build routing before the correction loop works. Routing multiplies whatever the correction loop produces. A broken loop routing to five specialists distributes broken behavior at five times the rate.
  • Do not skip the replay buffer. Every calibration run without it silently erases prior corrections. One extra parameter in the training batch. Add it at the start.
  • Do not lower C_min to appear more capable. C_min is a safety property. Lowering it produces confident wrong answers in domains where being wrong has consequences.
  • Do not build Arbiter stage 4 (empirical checks) first. External API calls are expensive and least reliable. Logical and mathematical checks catch the most impactful contradictions at near-zero cost.
  • Do not run parallel harness sessions against the same specialist. KV-cache contention extends per-call time by 2–3×. Run parallel sessions against different specialists on different ports.
