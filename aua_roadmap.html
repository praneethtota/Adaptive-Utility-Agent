    gpu: 0
    gpu_memory_utilization: 0.34
    field: software_engineering
  - name: math
    model: Qwen/Qwen2.5-7B-Instruct-AWQ
    port: 9002
    gpu: 0
    gpu_memory_utilization: 0.34

arbiter:
  model: Qwen/Qwen2.5-3B-Instruct-AWQ
  port: 9003

router:

blue_green:
  swe:   { delta: 0.025, T_min: 10, tau: 0.20 }

CLI
#04
aua serve — single command startup

Reads aua_config.yaml, starts all vLLM specialist servers, wires up the router and arbiter, and exposes the FastAPI endpoints. Like uvicorn main:app or flink run. No manual vLLM commands.

aua serve                          # uses aua_config.yaml in cwd
aua serve --config ./my_config.yaml
aua serve --tier macbook           # uses built-in MacBook template

aua init --tier quad-4090     # 4x RTX 4090 small production

Security + Observability

Planned 18 items
Security
#15
Session IDs — end-to-end query tracking

Every query gets a unique UUID session ID generated at the router. Tracked through router → field classifier → specialist(s) → arbiter → correction loop → response. Used for audit logging, replay, and distributed tracing correlation.

securityops
#16
mTLS — encrypted internal communication

All internal component communication (router ↔ specialists, router ↔ arbiter, arbiter ↔ correction loop) encrypted with mutual TLS. Certificates auto-generated on aua init, stored in config-specified path. No plaintext internal traffic.

aua/
  certs/
    ca.crt
    router.crt / router.key
    swe.crt    / swe.key
    arbiter.crt / arbiter.key
securityinfra
#17
IAM and bearer token authentication

External API endpoints require signed bearer tokens. Token scopes control access level. Tokens verified on every request before query processing begins.

aua:query   # submit queries (standard users)
aua:admin   # deploy, config changes, blue-green triggers
aua:read    # metrics and health endpoints only
security
#18
Token management CLI

Generate, list, and revoke API tokens from the command line. Tokens are signed JWTs. Revocation is immediate via a blocklist checked on every request.

aua token create --scope aua:query --expires 30d
aua token list
aua token revoke <token-id>

aua_config.yaml references secret names, not values. Secrets loaded from env vars or a secrets manager. Supports: environment variables, HashiCorp Vault, AWS Secrets Manager, GCP Secret Manager. Import existing libraries: hvac (Vault), boto3 (AWS), google-cloud-secret-manager (GCP).

Every API call, routing decision, correction, and blue-green promotion logged with: session ID, token ID, timestamp, specialist, field, utility score, verdict, latency. Append-only. Hash-chained for tamper evidence. Required for DSA compliance.

Stage 3

High Availability

KRaft consensus for leader election, Kubernetes mode with Helm, circuit breakers, automatic failover, shared state via etcd.

Planned 14 items

Library-first principle. Nothing in Stage 3 is built from scratch. We import and wire existing production-grade libraries: kafka-python or confluent-kafka for KRaft, etcd3 for shared state, python-consul for service discovery, tenacity for retry logic, circuitbreaker for circuit breaking. Our contribution is the AUA-specific wiring and config surface, not the consensus algorithms.

Consensus and coordination
#33
KRaft consensus for coordinator election

Use Apache Kafka's KRaft mode (via confluent-kafka) as the coordination layer. Router, arbiter, and blue-green controller elect a leader. If leader dies, a follower takes over automatically. No ZooKeeper required. Election completes in under 5 seconds.

ha:
  mode: kraft
  kafka:
    brokers: ["kafka1:9092", "kafka2:9092"]
  replicas:
    router: 3
    arbiter: 2
infracode
#34
Leader election for router and arbiter

Multiple router replicas run simultaneously. One is elected leader via etcd or KRaft. Leader handles blue-green promotion decisions and config changes. Follower routers continue serving queries throughout any election. Import etcd3 for the lock primitive.

infracode
#35
Shared state via etcd

Domain confidence EMA, active corrections, blue-green traffic split ratios stored in etcd so all router replicas see the same values. No stale routing decisions from lagging replicas. Import etcd3 — drop-in key-value store with watch support.

ha:
  etcd:
    endpoints:
      - "http://etcd1:2379"
      - "http://etcd2:2379"
      - "http://etcd3:2379"
infracode
#36
Service discovery via Consul

Specialists register themselves with Consul on startup. Router discovers specialist endpoints dynamically from Consul rather than hardcoded config. New specialists added to the graph without router restart. Import python-consul.

infracode
Failure handling
#37
Circuit breaker per specialist endpoint

Prevents cascade failures when a specialist is slow or flapping. After N failures, circuit opens and router stops calling that specialist. After recovery timeout, circuit half-opens and tests with one request. Import circuitbreaker library.

ha:
  circuit_breaker:
    failure_threshold: 5
    recovery_timeout: 30s
    half_open_max_calls: 1
infracode
#38
Automatic failover with health-based routing

Consul health checks detect a dead specialist within 10 seconds. Router automatically stops routing to it. When it recovers, Consul marks it healthy and router resumes. No manual intervention. Dead specialist's load redistributes to the arbiter and general fallback automatically.

infraops
#39
Retry logic with exponential backoff

All inter-component calls (router → specialist, router → arbiter) retried automatically on transient failures. Exponential backoff with jitter prevents thundering herd. Import tenacity — decorator-based, no boilerplate.

Multi-tenancy — isolated namespaces per tenant

Isolated namespaces per tenant on shared infrastructure. Tenant-specific field configs, correction stores, DPO histories, and U score histories. Tenant ID derived from token scope. Critical for SaaS deployments where multiple orgs share the same specialist graph.

Cache responses for semantically similar queries using Redis + embedding similarity. Reduces GPU load significantly at scale. Cache keyed on embedding similarity above a threshold (default 0.95). Import redis and any embedding model already loaded as a specialist.

Extensibility
#51
Plugin system — custom specialists and detectors

Users register custom specialists, custom contradiction detectors, and custom utility functions without modifying core framework code. Decorator-based registration, same pattern as FastAPI routers or Flask blueprints.

from aua import specialist, detector

@specialist(field="robotics", port=9008)
class RoboticsSpecialist:
    async def generate(self, query: str) -> str: ...

@detector(fields=["robotics"])
class KinematicsContradictionDetector:
    def check(self, problem: str, solution: str): ...

#52
Middleware pipeline

Pre/post processing hooks on every query, like FastAPI's middleware. Users add logging, PII scrubbing, custom auth, query transformation, response filtering without touching framework internals.

from aua import middleware

@middleware("pre_query")
async def scrub_pii(query: str) -> str:
    return pii_scrubber.clean(query)

@middleware("post_response")
async def add_disclaimer(response: dict) -> dict:
    response["disclaimer"] = "AI-generated content."
    return response
