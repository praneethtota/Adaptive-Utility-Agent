Part 1 Quickstart ~8 min

Install, scaffold a project, verify your setup, and start the router. You will have a live HTTP endpoint before you read the next paragraph.

1.1 Install

Python version: AUA requires Python 3.11+. If you use pyenv, set the version before installing — otherwise aua will be installed into a Python version that isn't your active shell default.

bash
# If using pyenv — set Python 3.11+ first
pyenv local 3.11.10       # or: pyenv global 3.11.10

# Install AUA
pip install "adaptive-utility-agent[dev]"

# Verify
aua --version
aua, version 0.7.0b0

New directory? If you create a fresh project directory and aua suddenly becomes "command not found", pyenv has switched back to your global Python. Fix: cd your-project && pyenv local 3.11.10. This writes a .python-version file so the directory always uses 3.11.

Part 2 Models & Fields ~12 min

A specialist is a language model that answers queries in a specific domain. A field defines the stakes: how confident must the model be before it answers, and how hard should errors be penalized?

2.1 What's in aua_config.yaml

aua_config.yaml — macbook tier
aua:
  version: "0.6"
  mode: local
  backend: ollama          # "vllm" | "ollama"

specialists:
  - name: swe              # unique name — used in routing, logs, API
    model: qwen2.5-coder:7b
    port: 11434            # Ollama: all specialists share one port
    field: software_engineering   # maps to FIELD_CONFIGS key
    gpu: 0

  - name: math
    model: qwen2.5:7b
    port: 11434
    field: mathematics

arbiter:
  model: qwen2.5:3b
  port: 11434

router:
  port: 8000
  single_domain_threshold: 0.75   # route to single specialist above this
  fanout_threshold: 0.30          # fan out to multiple when both fields above this

2.2 Built-in fields and their weights

Each field configures how U = w_e·E + w_c·C + w_k·K is evaluated. High-stakes fields weight confidence more heavily and penalize errors harder.

2.4 Adding a new specialist

Adding a domain is three steps: add a specialist to aua_config.yaml, pick a field from FIELD_CONFIGS (or plan a custom one for v0.8+), restart.

aua_config.yaml — add law specialist (macbook tier)
specialists:
  - name: swe
    model: qwen2.5-coder:7b
    port: 11434
    field: software_engineering

  - name: math
    model: qwen2.5:7b
    port: 11434
    field: mathematics

  - name: law                      # NEW
    model: qwen2.5:7b              # same model, different field weights
    port: 11434
    field: law                     # c_min=0.85, penalty=5x

Ollama shared port: all Ollama specialists share port 11434. Ollama distinguishes them by model tag in the request body. The duplicate-port validator in AUA automatically exempts Ollama backends.

Part 3 Routing & Utility ~15 min

3.1 The three routing modes

Every query goes through three stages: field classification → routing decision → specialist call → utility scoring.

ModeWhenWhat happens
singleOne field scores above single_domain_threshold (0.75)Query goes to that specialist only
fanoutTwo+ fields both above fanout_threshold (0.30)Query sent to all qualifying specialists; best U score wins
arbiterFanout returned contradictory answersArbiter resolves the conflict, issues a correction

3.2 Force a routing mode for testing

bash — force single domain
curl -s -X POST http://localhost:8000/query \
  -H "Content-Type: application/json" \
  -d '{
    "query": "Prove the Pythagorean theorem.",
    "force_domain": "mathematics"
  }' | python3 -m json.tool

3.3 The utility function

U = w_e·E + w_c·C + w_k·K — three terms, field-weighted:

  • E (Efficacy) — how well did this answer perform relative to baseline? Mann-Whitney dominance probability over prior outputs. Range [0, 1].
  • C (Confidence) — Kalman-filtered internal consistency score, penalized on each contradiction detected. Range [0, 1].
  • K (Curiosity) — UCB-style exploration bonus for high-upside uncertain domains. Capped at 50% of total U to preserve exploitation dominance.

U is a control signal, not a metric. It directly gates whether a model promotes to production (blue-green), determines DPO pair weight during training, and controls whether the arbiter escalates a verdict.

Part 4 The Arbiter & Corrections ~15 min

When fanout routing produces contradictory responses from two specialists, the Arbiter runs four checks, issues a verdict, and injects correction signals back into both models. This is the core online learning mechanism.

4.1 The four arbitration checks

CheckWeightWhat it detects
Logical0.30Does the output contradict its own premises?
Mathematical0.40Are complexity / numerical claims provably wrong?
Cross-session0.20Contradicts a prior verified assertion?
Empirical0.10External ground truth check (roadmap Phase 1)

4.2 The four verdict cases

CaseMeaningAction
Case 1A correct, B wrongCorrect B, reinforce A, store verified claim
Case 2B correct, A wrongCorrect A, reinforce B, store verified claim
Case 3Both wrongCorrect both + open curiosity gap bonus
Case 4InconclusiveFlag for external escalation, hedge response

4.3 Using the Arbiter directly

Python
from aua import ArbiterAgent, AssertionsStore

store = AssertionsStore()
arbiter = ArbiterAgent(store)

verdict = arbiter.arbitrate(
    subject="bubble_sort_complexity",
    domain="software_engineering",
    output_A="Bubble sort is O(n) average case.",
    output_B="Bubble sort is O(n²) average case.",
    field_penalty_multiplier=2.0,
)

print(verdict.case.value)         # "case_1", "case_2", "case_3", or "case_4"
print(verdict.correct_A)          # True if A should receive a correction
print(verdict.verified_claim)     # Verified answer, or None if inconclusive
print(verdict.external_response)  # What the user sees (always safe to show)

4.4 The assertions store — cross-session memory

Verified claims are stored with a field-specific decay class:

ClassDecay τUsed for
ANeverMathematical proofs, algorithm correctness
B10 yearsClassical physics, structural engineering
C3 yearsMedicine, law, architecture
D6 monthsSecurity CVEs, clinical guidelines, ML benchmarks
Python — query the assertions store
from aua import AssertionsStore

store = AssertionsStore()
# After arbitration has stored some facts:
matches = store.query("bubble_sort", domain="software_engineering")
for m in matches:
    print(f"{m.assertion.claim[:60]}  (conf={m.effective_confidence:.2f})")

Part 5 Blue-Green Deployment ~20 min

Blue-green deployment is how AUA promotes new model versions. The BLUE model is in production. A GREEN candidate runs against canary traffic. When GREEN's utility score exceeds BLUE by delta over at least T_min interactions, it promotes.

5.1 Promotion thresholds

Configured per-specialist under blue_green: in aua_config.yaml:

aua_config.yaml
blue_green:
  swe:
    delta: 0.025    # GREEN must beat BLUE by +2.5% U to promote
    T_min: 10       # need at least 10 canary interactions
    tau: 0.20       # softmax temperature for traffic split

5.2 Using BlueGreenDeployment

Python
from aua import BlueGreenDeployment
from aua.config import load_config

config = load_config("aua_config.yaml")
bg = BlueGreenDeployment(config, specialist_name="swe")

print(f"BLUE model:       {bg.blue_model}")
print(f"Delta threshold:  {bg.delta_threshold}")  # 0.025
print(f"T_min:            {bg.t_min}")             # 10

# Register a candidate GREEN model
bg.register_green("models/swe-green-v2/")

# Evaluate (full harness arrives in v0.8 — currently returns dry_run=True)
import asyncio
summary = asyncio.run(bg.evaluate(n_queries=10))
print(f"dry_run: {summary.dry_run}")  # True until harness built

# When evaluation harness is live:
if bg.should_promote(summary):
    bg.promote()
    print("GREEN promoted to BLUE")

5.3 The promotions log

Every promotion is recorded atomically to .aua/state/promotions.jsonl with a UUID and timestamp. The file is append-only and file-locked to prevent concurrent write corruption.

bash — inspect promotion history
cat .aua/state/promotions.jsonl | python3 -m json.tool

5.4 Rollback

bash
aua rollback --specialist swe          # interactive confirm
aua rollback --specialist swe --yes    # skip confirm
aua rollback --dry-run                 # preview only — no changes
aua rollback --all --yes               # roll back every specialist

Rollback reads the promotions log, reverts aua_config.yaml to the previous BLUE model using an atomic .tmp → os.replace() write, and restarts the specialist server.

The full evaluation harness (automated canary scoring) is roadmap item #14, arriving in v0.8. In v0.7, BlueGreenDeployment.evaluate() returns dry_run=True. You can trigger manual rollbacks and record promotions manually today.

Part 7 The Correction Loop ~15 min

The correction loop closes the gap between detected errors and model improvement. It collects contradiction events from the router, formats them as DPO training pairs, and exports them for the next fine-tuning cycle.

7.1 How corrections accumulate

Every time the Arbiter issues a correction (Cases 1, 2, 3), it stores the verified claim in the assertions store and the DPO pair is available via the router's /corrections endpoint. In fanout mode, corrections happen automatically in the background.

bash — check accumulated corrections
curl http://localhost:8000/corrections | python3 -m json.tool

7.2 Using CorrectionLoop

Python
import asyncio
from aua import CorrectionLoop
from aua.config import load_config

config = load_config("aua_config.yaml")
loop = CorrectionLoop(config, router_url="http://localhost:8000")

async def main():
    # Collect high-confidence pairs from the router
    pairs = await loop.collect_pairs(min_confidence=0.8)
    print(f"Collected {len(pairs)} pairs")

    # Export to JSONL for DPO training
    summary = loop.export_pairs(pairs, output_dir="dpo_pairs")
    print(f"Exported to: {summary.output_path}")
    print(f"Domains: {summary.domains}")

asyncio.run(main())
Collected 7 pairs Exported to: dpo_pairs/dpo_pairs_20260511_143022.jsonl Domains: ['software_engineering', 'mathematics']

7.3 DPO pair format

Each exported file is JSONL with one record per line:

dpo_pairs/dpo_pairs_*.jsonl
{"prompt": "bubble_sort_complexity", "chosen": "Bubble sort is O(n²) average case.", "rejected": "", "domain": "software_engineering", "confidence": 0.91, "source": "arbiter"}
{"prompt": "heapsort_complexity", "chosen": "Heapsort is O(n log n) worst-case.", "rejected": "", "domain": "software_engineering", "confidence": 0.99, "source": "manual"}

Training integration (v0.8): CorrectionLoop.train() will trigger LoRA fine-tuning on the affected specialist and hand off to BlueGreenDeployment for evaluation. For now, export the pairs and pass them to your preferred training pipeline (TRL, Axolotl, Unsloth).

7.4 Field-specific penalty weights in training

When you pass DPO pairs to your trainer, use penalty_multiplier from FIELD_CONFIGS as the loss weight. A surgical error should update the model 10× harder than a creative writing mistake:

for pair in pairs:
    field_cfg = FIELD_CONFIGS.get(pair.domain, FIELD_CONFIGS["general"])
    loss_weight = field_cfg.penalty_multiplier
    # pass loss_weight to your DPO trainer's per-sample weight

Part 9 Security ~10 min

9.1 CORS configuration

By default CORS allows all origins (["*"]). In production, restrict to your frontend domain:

aua_config.yaml
router:
  port: 8000
  cors_origins:
    - "https://my-app.example.com"
    - "https://admin.example.com"

cors_origins is hot-reloadable — change it and run aua config reload without restarting.

Doctor warning on unsafe settings: If you run with cors_origins: ["*"] and host: "0.0.0.0" on a public IP, aua doctor will warn loudly. This combination exposes the router to the internet with no access control.

9.2 Secrets (roadmap #19 — v0.8)

In v0.7, all config values are plaintext in aua_config.yaml. The planned secrets system references environment variables or a vault:

aua_config.yaml — planned v0.8 secrets syntax
secrets:
  provider: env              # "env" | "vault" | "aws" | "gcp"

# Reference secrets by name, not value:
api_key_secret: OPENAI_API_KEY   # reads from $OPENAI_API_KEY

Until v0.8 ships: use Docker Compose environment files (.env) and never commit credentials to git.

9.3 GET /config redaction

The GET /config endpoint is already designed to be safe — it returns the structural config without sensitive runtime values. The /corrections endpoint returns claims without evidence chains (those are internal-only).

9.4 Port exposure

In production, only the router port (8000) should be public. Specialist ports (9001–9003 for vLLM, 11434 for Ollama) are internal and should be firewalled.

docker-compose.yml — production port exposure
services:
  router:
    ports:
      - "8000:8000"    # public
  swe:
    # No ports: — internal only, accessible within Docker network only
  arbiter:
    # No ports: — internal only

12.3 Systemd service (non-Docker)

/etc/systemd/system/aua.service
[Unit]
Description=AUA Framework Router
After=network.target

[Service]
User=aua
WorkingDirectory=/opt/aua
ExecStart=/opt/aua/.venv/bin/aua serve
ExecReload=/bin/kill -HUP $MAINPID   # hot-reload on systemctl reload aua
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
bash — control the service
systemctl start aua
systemctl reload aua    # hot-reload config (sends SIGHUP)
systemctl status aua
journalctl -u aua -f    # follow logs
